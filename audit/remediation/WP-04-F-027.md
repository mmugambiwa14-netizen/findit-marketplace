# WP-04 — F-027 server-side administrator MFA assurance

Status: **PARTIAL / UNPROVEN until database CI executes**

## Finding

The React MFA gate prevented ordinary UI navigation but `private.is_admin()` and `private.is_super_admin()` did not inspect the JWT assurance level. A stolen administrator password could therefore use an aal1 access token to call administrator RPCs directly even when a verified factor existed.

## Fix shape

- Add a private security-definer helper that reads verified enrolment from `auth.mfa_factors`.
- Add a private assurance helper that requires `auth.jwt() ->> 'aal' = 'aal2'` once a verified factor exists.
- Centralize enforcement in the existing `private.is_admin()` and `private.is_super_admin()` helpers so dependent RLS policies and RPCs inherit the control.
- Preserve the no-factor enrolment/recovery path rather than unconditionally locking all administrators behind aal2.
- Preserve the existing browser gate and `/reset-password` exemption.

## Required proof

The committed pgTAP suite must pass after a clean database reset and demonstrate:

1. an administrator without a verified factor can still access enrolment paths at aal1;
2. the same administrator is denied at aal1 after a verified factor exists;
3. the administrator is allowed at aal2;
4. an ordinary user is denied even at aal2;
5. an actual administrator RPC follows the same behavior, not only the helper predicate.

## Deliberately not done

- The client-side fail-closed MFA gate was not weakened or removed.
- Password reset routing was not changed.
- No browser-supplied role or MFA state was trusted.
- No direct grant was added for the new private helper functions.
- F-027 is not marked DONE until the database suite executes.
