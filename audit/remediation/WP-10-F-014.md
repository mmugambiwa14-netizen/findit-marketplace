**These are type-soundness gaps, not proven runtime defects.** The code works; TypeScript simply could not
see the shapes. Reported that way in the audit and unchanged here.

### Two distinct causes, not one

The audit attributed all 10 to `useMutation` generic inference. That is right for 9 of them. The tenth —
`BusinessProfiles.jsx:33` — is unrelated:

- **9 errors: `TVariables` defaults to `void`.** TanStack Query v5 declares
  `useMutation<TData, TError, TVariables = void, TContext>`. `TVariables` is inferred from
  `mutationFn: (variables: TVariables) => …`. When the parameter has no annotation there is nothing to infer
  from, so it falls back to the declared default `void` — and every read off that parameter becomes a read
  off `void`.
- **1 error: a custom property on `Error`.** `saveOwnerBusinessProfile` throws
  `Object.assign(new Error(…), { cause: error, profileSaved: true })`
  (`src/services/businessProfilesService.js:100-103`) so the caller can distinguish "profile saved, logo
  failed" from a total failure. `profileSaved` is real at runtime but not declared on `Error`.

## 2. What changed — reusing conventions already in the repository

Both fixes follow patterns this codebase already uses. Nothing new was invented (sourcing priority 2).

| File | Change | Existing pattern followed |
|---|---|---|
| `src/components/peekThreads/BuyerPeekRequestsQueue.jsx` | `@typedef SellerQueueItem` documenting the real queue row, then `(/** @type {SellerQueueItem} */ item)` on the `accept` and `cancel` mutations | `src/components/messaging/ConversationThread.jsx:139` — `mutationFn: (/** @type {boolean} */ blocked) => …` |
| `src/pages/BusinessProfiles.jsx` | `@typedef SaveProfileVariables`, applied to the destructured `mutationFn` parameter | same |
| `src/types/runtime-extensions.d.ts` | `profileSaved?: boolean` added to the global `Error` interface | the file already declares `code`, `correlationId`, `retryable`, `status`, `context`, `validationErrors`, `resumeUpload` for exactly this purpose |

The `SellerQueueItem` shape is not invented either — it is transcribed from
`src/domain/peekThreads/sellerQueueContracts.js:18-39`, the function that actually builds these rows
(`normalizeSellerPeekQueuePage`), including the nullable `fulfilment` sub-object. The typedef is declared in
the component rather than imported from `src/domain`, because `src/domain` sits outside the `include` list
in `jsconfig.json` and pulling it into the checked graph would have widened this package's blast radius.

**No runtime behaviour changed.** Every edit is a JSDoc annotation or a `.d.ts` declaration; the emitted
JavaScript is byte-identical.

## 4. Deliberately not done

- **`src/services/businessProfilesService.js` was not annotated.** Adding the `profileSaved` declaration to
  the shared `Error` interface is how this repository already models augmented errors, and it fixes the
  error at every call site rather than one. Typing the service module would have pulled `src/services` into
  the checked graph — outside this package's scope.
- **No `useMutation` call elsewhere was touched.** The other 9 call sites in `src/` pass no variables
  (`mutationFn: () => …`), so `TVariables = void` is correct for them and annotating would be noise.
- **The two typedefs are not shared.** They describe two unrelated shapes used in one file each. Hoisting
  them into a shared types module would create a dependency for no current benefit.
